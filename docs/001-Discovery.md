# سند دیسکاوری — Resume Maker Minimal
**نسخه:** 1.0  |  **تاریخ:** 28 اکتبر 2026  |  **وضعیت:** پیش‌نویس اولیه  |  **زبان:** فارسی

---

## 0. خلاصه اجرایی (Executive Summary)

پروژه **Resume Maker Minimal** یک نرم‌افزار متن‌باز و سبک برای ساخت رزومه‌های حرفه‌ای است که با C# و فناوری Native AOT توسعه می‌یابد. هدف اصلی، ارائه ابزاری مینیمال، بدون وابستگی سنگین جانبی، و قابل اجرا به‌صورت باینری واحد روی ویندوز و لینوکس است. کاربر می‌تواند از میان چند قالب از پیش طراحی‌شده یکی را انتخاب کند، یا با الگوی نوآورانه **Lead-Based AI Workflow**، یک پرامپت ساختاریافته دریافت کرده، با هر AI دلخواه خود (ChatGPT, Claude, Gemini) قالب اختصاصی HTML/CSS بسازد و فایل HTML تولیدشده را به اپ وارد کند.

خروجی نهایی به‌صورت HTML/CSS Inline کاملاً استاتیک (بدون JavaScript) است تا قابل میزبانی روی هر سرویس استاتیک (GitHub Pages، Netlify، AWS S3) باشد. اپ امکان Export به PDF و تصویر (PNG) را نیز فراهم می‌کند. زبان پیش‌فرض فارسی با فونت Vazir است، اما کاربر می‌تواند با یک کلیک به انگلیسی سوئیچ کند. سکشن‌های پیشنهادی از پیش تعبیه‌شده (درباره من، مهارت‌ها، زبان‌ها، تجربه کاری، تحصیلات، پروژه‌ها، جوایز) فرآیند ورود اطلاعات را سریع می‌کنند.

این سند دیسکاوری، حاصل جمع‌بندی نیازمندی‌های کسب‌وکار، مخاطبان، Use Caseها و محدودیت‌هاست و مبنای سند معماری بعدی قرار می‌گیرد. در پایان این سند، reader باید بتواند به‌وضوح بگوید چه چیزی ساخته می‌شود، برای چه کسی، با چه محدودیت‌هایی، و چه موفقیتی معنی می‌دهد.

## 1. پس‌زمینه و انگیزه (Background & Motivation)

### 1.1 وضعیت موجود

بازار ابزارهای ساخت رزومه اشباع شده اما اکثر گزینه‌های موجود یا SaaS پولی با مدل اشتراکی (Zety, Resume.io, Canva) هستند، یا ابزارهای اوپن‌سورس با وابستگی‌های سنگین (React/Vue + Node backend + DB) که راه‌اندازی لوکال آن‌ها برای کاربر نهایی سخت است. هیچ‌کدام از این ابزارها به‌صورت باینری تک‌فایلری روی دسکتاپ و وب با پشتیبانی Native AOT ارائه نشده‌اند.

ابزارهای دسکتاپ موجود (مثل Novoresume، Resume Builder) معمولاً با Electron توسعه می‌یابند که حجم باینری 150+ مگابایت و مصرف رم بالایی دارد. این در تضاد با اصل "مینیمال بودن" که کاربر در این پروژه درخواست کرده است، قرار دارد. از طرف دیگر، ابزارهای تحت وب معمولاً به اینترنت و حساب کاربری نیاز دارند، که برای کاربر ایرانی با محدودیت دسترسی یا نگرانی حریم خصوصی مناسب نیستند.

### 1.2 شکاف بازار و فرصت

شکاف اصلی در این بازار، نبود ابزاری است که سه ویژگی را هم‌زمان داشته باشد: (1) سبک و Native AOT بدون runtime، (2) فارسی‌محور با پشتیبانی RTL و فونت Vazir به‌صورت بومی، (3) امکان شخصی‌سازی قالب با AI بدون نیاز به اتصال مستقیم به پروایدر. الگوی **Lead-Based AI Workflow** این شکاف را پر می‌کند: کاربر به جای محدود شدن به قالب‌های پیش‌فرض، پرامپت تولیدشده توسط اپ را می‌گیرد، با هر AI که به آن اعتماد دارد کار می‌کند، و خروجی را وارد می‌کند. این یعنی صفر وابستگی به APIهای پولی، صفر نگرانی حریم خصوصی، و حداکثر انعطاف در شخصی‌سازی.

### 1.3 انگیزه فنی

از منظر فنی، این پروژه فرصتی برای اثبات پختگی Native AOT در دات‌نت برای اپ‌های واقعی با UI است. تا پیش از این، اکثر نمونه‌های Native AOT یا CLI محض بودند یا بدون UI، و الگوهای بهترین برای ترکیب Native AOT با UI Frameworkها (Avalonia، WinUI) و کتابخانه‌های رندر (PDF/Image از HTML) هنوز به‌خوبی مستند نشده‌اند. این پروژه می‌تواند به‌عنوان reference implementation برای جامعه دات‌نت فارسی‌زبان عمل کند.

## 2. مخاطبان و Personas

### 2.1 Persona اصلی: «مریم، 24 ساله، دانشجوی ارشد»

مریم دانشجوی ارشد کامپیوتر در تهران است و در حال آماده‌سازی رزومه برای درخواست کار در شرکت‌های تکنولوژی ایرانی و خارجی است. او تجربه استفاده از Canva و Zety را دارد اما از اشتراک پولی و تبلیغات خسته شده. مریم به دنبال ابزاری است که: رزومه فارسی و انگلیسی به‌طور هم‌زمان بسازد، خروجی PDF تمیز بدهد که قابل آپلود در Jobinja و LinkedIn باشد، و نیاز به ثبت‌نام نداشته باشد. او آشنایی متوسط با تکنولوژی دارد و می‌تواند یک فایل HTML را وارد اپ کند، اما نه حوصله و نه دانش کدنویسی مستقیم قالب را دارد.

### 2.2 Persona فرعی: «علی، 32 ساله، توسعه‌دهنده سنیور»

علی 10 سال سابقه دارد و می‌خواهد رزومه‌ای کاملاً سفارشی با حس و حال تکنیکال (مشابه resume شاملیت ساعت‌ها) بسازد. او می‌خواهد لینک GitHub، نمودار Contributions، Stack آپدیت‌شده و QR کد به پروفایل LinkedIn را در رزومه داشته باشد. علی به Native AOT و سبکی بودن اپ اهمیت می‌دهد چون از ابزارهای سنگین Electron متنفر است. او از الگوی Lead-Based به‌خصوص خوشش می‌آید چون می‌تواند با Claude خودش قالب اختصاصی بسازد.

### 2.3 Persona آینده: «زهرا، 28 ساله، طراح UX»

زهرا می‌خواهد رزومه خودش را با حس و حال portfolio-style بسازد و تصاویر نمونه کارها را در خود رزومه جا دهد. در MVP فعلی پشتیبانی از تصاویر در رزومه حداقمی است، اما پلن آینده (Post-MVP) امکان portfolio template را فراهم می‌کند. زهرا به‌خاطر شناختش از CSS می‌تواند HTML خروجی از AI را شخصاً ویرایش کند و وارد اپ کند.

### 2.4 غیر‌Persona (Anti-Persona)

این پروژه برای تیم‌های HR که می‌خواهند هزاران رزومه را پردازش کنند مناسب نیست. همچنین برای شرکت‌هایی که نیاز به رزومه‌ساز سفارشی با برند سازمانی دارند طراحی نشده. نهایتاً، کاربرانی که انتظار collaboration زنده یا cloud sync دارند نیز از target خارج می‌شوند؛ این اپ آفلاین-محور است.

## 3. اهداف محصول و معیارهای موفقیت

### 3.1 اهداف کیفی (Qualitative Goals)

هدف اول، ارائه تجربه‌ای روان و بدون اصطکاک در ساخت رزومه است. کاربر باید بتواند از نصب تا خروجی اولین PDF در کمتر از 5 دقیقه برسد. هدف دوم، حفظ مینیمالیسم است؛ یعنی اپ نباید هیچ فیچر اضافه یا پیکربندی گیج‌کننده داشته باشد. هدف سوم، حفظ استقلال کامل از سرویس‌های آنلاین است؛ یعنی اپ بدون اتصال به اینترنت کار کند، به‌جز Export اپشنال به سرویس‌های ذخیره‌سازی ابری (Nextcloud، S3) که در نسخه آینده اضافه می‌شود.

### 3.2 اهداف کمّی و KPIها

| معیار | هدف MVP | هدف 6 ماه پس از انتشار |
|-------|---------|-------------------------|
| حجم باینری ویندوز (Native AOT، 64-bit) | < 25 MB | < 22 MB |
| زمان راه‌اندازی اپ (Cold Start) | < 1.5 ثانیه | < 800 ms |
| مصرف RAM در حالت idle | < 80 MB | < 50 MB |
| زمان تولید PDF از HTML | < 3 ثانیه | < 1.5 ثانیه |
| تعداد قالب‌های از پیش طراحی‌شده | 5 | 12 |
| تعداد دانلود ماهانه (GitHub) | 500 | 5,000 |
| ستاره‌های GitHub در 6 ماه | — | 500+ |

### 3.3 معیار موفقیت کاربر-محور

موفقیت کاربر از سه زاویه سنجیده می‌شود: (1) کاربر بتواند رزومه‌ای تولید کند که از دید مصاحبه‌کننده حرفه‌ای به‌نظر برسد (با 10 مصاحبه‌کننده کاربر تست می‌شود)، (2) زمان تولید رزومه از صفر تا Export کمتر از 30 دقیقه باشد، (3) کاربر به‌صورت خودبه‌خودی به‌جای ابزار قبلیش به این اپ برگردد (Retention بعد از 30 روز > 40%).

## 4. محدوده (Scope)

### 4.1 در Scope (In-Scope) — MVP

MVP این پروژه شامل موارد زیر است: پنل مدیریت رزومه با قابلیت ورود اطلاعات در سکشن‌های استاندارد (درباره من، تجربه کاری، تحصیلات، مهارت‌ها، زبان‌ها، پروژه‌ها، جوایز)، پنج قالب پیش‌فرض با استایل‌های متفاوت (Minimal, Classic, Modern, Compact, Sidebar)، الگوی Lead-Based AI Workflow با تولید پرامپت کپی‌شدنی و Import HTML، Export به PDF و PNG با کیفیت بالا، Import/Export به JSON برای انتقال داده، Dark Mode برای preview اپ (بدون تاثیر روی خروجی)، پشتیبانی دوزبانه فارسی/انگلیسی با RTL/LTR خودکار، فونت Vazir به‌صورت embedded در HTML خروجی.

### 4.2 در Scope (In-Scope) — Post-MVP

مواردی که در نسخه‌های بعدی (v1.1 تا v2.0) اضافه می‌شوند: Cover Letter Generator با الگوی مشابه Lead-Based (تولید پرامپت، ورود خروجی)، QR Code embedding برای لینک‌ها، چندین رزومه موازی (Multi-Profile)، خروجی PDF در دو حالت "Designer PDF" (با گرافیک) و "ATS-Friendly PDF" (متن ساده بدون جدول و رنگ)، قالب‌های portfolio با تصاویر نمونه کار، سینک آپشنال با Dropbox/Google Drive، و Theme Builder پیشرفته برای تنظیم رنگ‌ها بدون کد.

### 4.3 خارج از Scope (Out-of-Scope)

این موارد به‌صورت اصولی از Scope خارج می‌شوند: Collaboration زنده بین چند کاربر، Cloud Backend اختصاصی برای ذخیره رزومه، اشتراک‌گذاری عمومی رزومه با URL (مگر در v2.0 با GitHub Pages export)، پشتیبانی از زبان‌های غیر از فارسی/انگلیسی در MVP (افزایش به 5 زبان در v1.5)، AI به‌صورت embedded (هیچ API key از کاربر گرفته نمی‌شود)، پشتیبانی از موبایل Native (iOS/Android) — نسخه تحت وب responsive در اولویت است.

## 5. Use Caseهای اصلی

### 5.1 UC-01: ساخت رزومه از صفر با قالب پیش‌فرض

**بازیگر:** کاربر (مریم)
**هدف:** تولید رزومه فارسی برای درخواست شغل
**پیش‌نیاز:** اپ نصب شده
**جریان اصلی:**
1. کاربر اپ را باز می‌کند و روی «رزومه جدید» کلیک می‌کند.
2. اپ یک شناسنامه خالی (Profile) می‌سازد و کاربر را به صفحه ویرایش هدایت می‌کند.
3. کاربر اطلاعات پایه را وارد می‌کند: نام کامل، عنوان شغلی، ایمیل، تلفن، شهر، لینک LinkedIn و GitHub.
4. اپ به‌صورت زنده preview را در سایدبار راست (یا چپ در حالت RTL) آپدیت می‌کند.
5. کاربر یکی از 5 قالب پیش‌فرض را از dropdown انتخاب می‌کند.
6. کاربر وارد سکشن «درباره من» می‌شود و یک پاراگراف 3-4 خطی می‌نویسد.
7. کاربر سکشن «تجربه کاری» را اضافه می‌کند، چندین آیتم وارد می‌کند (عنوان، شرکت، تاریخ، توضیح).
8. کاربر به‌طور مشابه تحصیلات، مهارت‌ها، زبان‌ها را پر می‌کند.
9. کاربر روی «Export PDF» کلیک می‌کند، مسیر ذخیره را انتخاب می‌کند.
10. اپ قالب را رندر می‌کند، Chrome/Edge headless را اجرا می‌کند، PDF تولید می‌شود.
11. اپ PDF را در مسیر انتخاب‌شده ذخیره می‌کند و یک toast می‌دهد.

**جریان‌های جایگزین:**
- 5a: کاربر می‌تواند قالب را قبل از Export تغییر دهد؛ preview فوراً آپدیت می‌شود.
- 9a: اگر Chrome نصب نباشد، اپ پیام راهنما نمایش می‌دهد و لینک دانلود را پیشنهاد می‌کند.
- 9b: کاربر می‌تواند به‌جای PDF، PNG یا HTML static انتخاب کند.

### 5.2 UC-02: ساخت قالب اختصاصی با الگوی Lead-Based AI

**بازیگر:** کاربر (علی)
**هدف:** داشتن قالب کاملاً سفارشی
**پیش‌نیاز:** کاربر به یک سرویس AI (ChatGPT, Claude) دسترسی دارد
**جریان اصلی:**
1. کاربر در اپ از منوی «قالب‌ها» روی «AI Template Builder» کلیک می‌کند.
2. اپ یک فرم تنظیمات باز می‌کند: سبک کلی (minimal, modern, classic, dark)، رنگ اصلی، رنگ اکسنت، فونت (فهرست محدود)، تعداد ستون‌ها (1 یا 2)، چیدمان sidebar (left/right)، اولویت سکشن‌ها (drag & drop).
3. کاربر تنظیمات را وارد می‌کند و روی «Generate Lead» کلیک می‌کند.
4. اپ یک پرامپت ساختاریافته چند段له‌ای تولید می‌کند که شامل موارد زیر است: معرفی نقش (system role)، توضیح پروژه (project brief)، اسکیمای داده JSON با مقادیر نمونه، تکنیکال constraintها (HTML inline، بدون JS، RTL/LTR، Vazir font embedded به‌صورت @font-face با base64 یا link به CDN)، اصول طراحی مینیمال، نمونه کد HTML برای یک سکشن.
5. کاربر دکمه «Copy to Clipboard» را می‌زند.
6. اپ پرامپت را در کلیپ‌بورد می‌گذارد و لینک به ChatGPT, Claude و Gemini را به‌عنوان shortcut نمایش می‌دهد.
7. کاربر به AI دلخواه می‌رود، پرامپت را paste می‌کند، خروجی HTML را دریافت می‌کند.
8. کاربر به اپ برمی‌گردد، روی «Import HTML» کلیک می‌کند، فایل HTML را انتخاب می‌کند.
9. اپ اعتبارسنجی HTML انجام می‌دهد: (a) آیا تگهای semantic درست هستند، (b) آیا placeholderهای مورد انتظار وجود دارند (مثل `{{name}}`، `{{experience}}`)، (c) آیا HTML valid است.
10. اگر اعتبارسنجی موفق باشد، اپ قالب را در کتابخانه قالب‌های سفارشی کاربر ذخیره می‌کند.
11. کاربر می‌تواند قالب را انتخاب، preview و Export کند.

**جریان‌های جایگزین:**
- 9a: اگر اعتبارسنجی شکست بخورد، اپ لیست خطاها را نمایش می‌دهد و راهنمایی می‌کند که چه چیزی در پرامپت فراموش شده.
- 9b: اپ می‌تواند HTML معیوب را در editor inline نمایش دهد تا کاربر (در صورت دانش) آن را تعمیر کند.

### 5.3 UC-03: تولید Cover Letter متناسب با شغل

**بازیگر:** کاربر (مریم)
**هدف:** تولید نامه پوششی برای درخواست خاص
**جریان اصلی:**
1. کاربر در Profile فعلی روی «Cover Letter Builder» کلیک می‌کند.
2. اپ یک فرم ساده باز می‌کند: نام شرکت، عنوان شغل، کلمات کلیدی از آگهی، لحن (formal, friendly, bold).
3. کاربر فرم را پر می‌کند و روی «Generate Lead» کلیک می‌کند.
4. اپ یک پرامپت تولید می‌کند که شامل: پروفایل خلاصه‌شده کاربر (JSON)، اطلاعات شغل، دستورالعمل لحن، محدودیت طول (یک صفحه A4)، ساختار پیشنهادی (پاراگراف باز، 2-3 پاراگراف میانه، پاراگراف بسته).
5. کاربر پرامپت را کپی می‌کند، با AI می‌سازد، برمی‌گرداند.
6. اپ متن را در یک editor متن ساده نمایش می‌دهد (با امکان ویرایش).
7. کاربر می‌تواند متن را ویرایش، Save و Export به PDF یا HTML کند.

### 5.4 UC-04: مدیریت چند رزومه (Post-MVP)

**بازیگر:** کاربر (علی)
**هدف:** نگهداری نسخه‌های مختلف رزومه برای موقعیت‌های متفاوت
**جریان اصلی:**
1. کاربر در داشبورد اصلی پروفایل «Software Engineer» را می‌بیند.
2. روی «New Profile» کلیک می‌کند، نام «Full Stack Developer — Startup» را وارد می‌کند.
3. اپ پرسش می‌کند: «از روی پروفایل فعلی کپی شود؟» کاربر «بله» را انتخاب می‌کند.
4. اپ یک کپی از پروفایل فعلی می‌سازد، در لیست پروفایل‌ها اضافه می‌کند.
5. کاربر می‌تواند هر پروفایل را مستقل ویرایش کند و Export بگیرد.

### 5.5 UC-05: خروجی ATS-Friendly PDF

**بازیگر:** کاربر (مریم)
**هدف:** ارسال رزومه به سیستم‌های ATS (Applicant Tracking Systems) شرکت‌ها
**جریان اصلی:**
1. کاربر در صفحه Export، گزینه «ATS-Friendly Mode» را تیک می‌زند.
2. اپ قالب فعلی را نادیده می‌گیرد و از قالب ساده متنی استفاده می‌کند (Helvetica/Arial، بدون جدول، بدون ستون، بدون رنگ).
3. اپ PDF را با متادیتای درست (نویسنده، عنوان، بدون پارامترهای امنیتی که متن را parse نکنند) تولید می‌کند.
4. اپ یک تأیید نشان می‌دهد که خروجی برای ATS بهینه شده است.

## 8. نیازمندی‌های غیرعملکردی (Non-Functional Requirements)

### 8.1 عملکرد (Performance)

اپ باید سبک و سریع باشد تا حس "Native" واقعی را منتقل کند. زمان راه‌اندازی (Cold Start) روی یک لپ‌تاپ متوسط (i5 8th gen، 8GB RAM، SSD) باید کمتر از 1.5 ثانیه باشد؛ این شامل زمان بارگذاری باینری Native AOT، initialization اولیه، و رندر صفحه اصلی است. زمان باز کردن یک Profile موجود باید کمتر از 300 میلی‌ثانیه باشد. رندر زنده preview در حین تایپ کاربر نباید بیشتر از 100 میلی‌ثانیه latency داشته باشد تا حس instant editing منتقل شود.

عملکرد Export نیز اهمیت دارد: تولید PDF برای رزومه‌ای با 3 صفحه، باید کمتر از 3 ثانیه طول بکشد (شامل زمان راه‌اندازی Chrome headless). اگر Chrome از قبل اجرا شده باشد، این زمان باید زیر 1 ثانیه باشد. اپ باید مکانیزمی برای نگه‌داشتن یک Chrome headless background داشته باشد (در v1.1) تا زمان Export کاهش یابد.

### 8.2 قابلیت حمل (Portability)

باینری Native AOT باید روی سه پلتفرم اجرا شود: Windows 10/11 x64، Linux x64 (Ubuntu 22.04 LTS و Debian 12 به‌عنوان مرجع)، و macOS x64/ARM64 (در v1.1). هیچ runtime جانبی (.NET، Visual C++ Redistributable، یا فریمورک‌های دیگر) نباید نیاز باشد. تنها وابستگی خارجی مجاز، Chrome/Edge (یا Chromium) نصب‌شده روی سیستم کاربر برای Export PDF است که در اسناد راهنما به‌صورت واضح توضیح داده می‌شود.

### 8.3 نگهداشت‌پذیری (Maintainability)

کد باید با اصول Clean Architecture و SOLID توسعه یابد. هر متد کمتر از 50 خط، هر کلاس Single Responsibility داشته باشد. تست واحد برای Core Library با xUnit و حداقل 70% coverage (بر اساس branches) الزامی است. نام‌گذاری فایل‌ها و کلاس‌ها باید مطابق الگوی PascalCase برای C# و snake_case برای JSON باشد. مستندات API به‌صورت XML comments و README.md در مخزن نگه‌داری شود.

### 8.4 امنیت و حریم خصوصی (Security & Privacy)

اپ نباید هیچ‌گونه داده‌ای را به سرور خارجی ارسال کند. هیچ تلمتری، crash report یا analytics آنلاین نباید به‌صورت پیش‌فرض فعال باشد (Opt-in در v1.1 اضافه می‌شود). داده‌های کاربر (Profile JSON) در پوشه‌ی محلی کاربر ذخیره می‌شود (در ویندوز `%APPDATA%/ResumeMaker`، در لینوکس `~/.local/share/ResumeMaker`، در مک `~/Library/Application Support/ResumeMaker`). هیچ رمز عبور یا token از کاربر گرفته نمی‌شود چون هیچ اتصال آنلاین یا AI integration مستقیمی وجود ندارد.

### 8.5 دسترس‌پذیری (Accessibility)

رابط کاربری باید با اصول WCAG 2.1 AA همخوان باشد. همه عملیات‌های اصلی باید با کیبورد قابل اجرا باشند. رنگ‌های تم Dark باید contrast ratio حداقل 4.5:1 با متن داشته باشند. تمام عناصر تعاملی باید label مناسب برای screen reader داشته باشند. در خروجی رزومه، ترتیب DOM باید معنادار باشد تا screen readerها بتوانند به‌درستی بخوانند.

### 8.6 بومی‌سازی (Localization)

رابط کاربری اپ به فارسی و انگلیسی ترجمه می‌شود. رشته‌ها در فایل‌های `.resx` نگه‌داری می‌شوند (یا فایل JSON ساده، که با Native AOT سازگارتر است). اپ باید زبان سیستم‌عامل را در اولین اجرا تشخیص دهد و تم و جهت را متناسب تنظیم کند. کاربر می‌تواند زبان UI و زبان رزومه را به‌صورت مستقل تنظیم کند.

### 8.7 قابلیت اطمینان (Reliability)

اپ نباید crash کند در سناریوهای رایج: ورود HTML معیوب از AI، Import JSON نامعتبر، حذف فایل Profile دستی توسط کاربر، یا نبود Chrome روی سیستم. در هر مورد، اپ باید با پیام خطای واضح به کاربر برگردد و راهنمایی ارائه دهد. مکانیزم backup خودکار هر 5 دقیقه از Profile فعلی در یک فایل temp نگه‌داری می‌شود تا در صورت crash، کاربر داده‌هایش را از دست ندهد.

### 8.8 سازگاری (Compatibility)

خروجی HTML باید در مرورگرهای مدرن (Chrome 100+، Firefox 100+، Safari 15+) به‌درستی نمایش داده شود. خروجی PDF باید در Adobe Reader، Foxit، و مرورگرهای داخلی在线 readerها قابل باز شدن باشد. فایل JSON خروجی باید UTF-8 با BOM نباشد تا در ابزارهای مختلف قابل خواندن باشد.

## 9. محدودیت‌ها و مفروضات (Constraints & Assumptions)

### 9.1 محدودیت‌های فنی

مهم‌ترین محدودیت فنی، انتخاب Native AOT است که چند پیامد دارد: (1) برخی کتابخانه‌های دات‌نت که به Reflection.Emit یا dynamic code gen وابسته‌اند (مثل Dapper با برخی features، System.Reflection.Emit clients، بعضی JSON libraryها) قابل استفاده نیستند. (2) JSON serialization باید با System.Text.Json و source generators انجام شود. (3) کتابخانه‌هایی که از reflection برای instantiate کردن typeها استفاده می‌کنند باید با AOT-friendly جایگزین شوند. (4) Some types of dependency injection (مثل Late-binding) باید با source-gen یا compile-time resolution جایگزین شوند.

محدودیت دوم، وابستگی به Chrome/Edge برای Export PDF است. این یعنی روی سیستم‌هایی که هیچ‌کدام نصب نیستند (مثلاً سرور headless لینوکس)، Export PDF کار نخواهد کرد مگر اینکه کاربر Chromium را نصب کند. در v1.1، اپ می‌تواند یک باینری Chromium embedded را به‌صورت opt-in bundle کند، اما این حجم اپ را به 80+ مگابایت می‌رساند که با اصل مینیمال در تضاد است. در MVP، کاربر مسئول نصب Chrome است.

محدودیت سوم، عدم وجود AI مستقیم است. این یعنی user experience برای ساخت قالب اختصاصی به‌صورت seamless نخواهد بود (کاربر باید به‌صورت دستی به AI برود و برگردد)، اما این فدا برای حفظ مینیمالیسم و عدم وابستگی به API key گرفته شده است.

### 9.2 مفروضات

مفروض اول، این است که کاربران هدف (افراد و دانشجوها) یا Chrome/Edge از قبل نصب دارند یا مایل به نصب آن هستند. در غیر این صورت، Export PDF کار نخواهد کرد. مفروض دوم، این است که کاربران برای الگوی Lead-Based، به یک سرویس AI رایگان (ChatGPT free tier، Claude free) دسترسی دارند. مفروض سوم، این است که کاربر ایرانی می‌تواند فونت Vazir را به‌صورت embedded در HTML خروجی داشته باشد (حجم فونت کامل Vazir مات حدود 100 کیلوبایت است که در HTML inline قابل قبول است).

## 11. ریسک‌ها و ابهامات (Risks & Open Questions)

### 11.1 ریسک‌های فنی

**ریسک R1: Native AOT و Avalonia UI compatibility.** با وجود پشتیبانی رسمی، برخی سناریوها (مثل dynamic loading of XAML، یا some hot reload) با AOT کار نمی‌کنند. این ریسک با prototype زودهنگام در هفته اول پروژه کاهش می‌یابد. اگر شکست بخورد، fallback به ReadyToRun (R2R) با trim است که بیشتر ولی نه تمام مزایای AOT را حفظ می‌کند.

**ریسک R2: PDF Export با Chrome headless.** اگر Chrome نصب نباشد، اپ باید به‌خوبی fail کند. راهکار: پیاده‌سازی a fallback به wkhtmltopdf (سبک‌تر، ولی رندر قدیمی‌تر WebKit). این fallback در v1.1 اضافه می‌شود.

**ریسک R3: حجم HTML inline با فونت Vazir embedded.** اگر فونت به‌صورت base64 در HTML inline قرار گیرد، حجم فایل می‌تواند به 200+ کیلوبایت برسد. راهکار: فقط glyp subset مورد استفاده (با fonttools) embedded شود، یا فونت از CDN لود شود در حالت online و inline در حالت offline.

### 11.2 ریسک‌های محصولی

**ریسک R4: مقبولیت الگوی Lead-Based.** برخی کاربران ممکن است از رفت‌وآمد بین اپ و AI خسته شوند. این ریسک با UX خوب (ساده‌سازی copy/paste، لینک‌های مستقیم، auto-detect clipboard) کاهش می‌یابد. در v1.1 می‌توان یک اپشنال API key برای OpenAI/Claude در نظر گرفت (Opt-in).

**ریسک R5: رقابت با Canva و ابزارهای رایگان.** اگر کاربر احساس کند با Canva راحت‌تر است، ممکن است به آن برگردد. راهکار: تمرکز روی نقاط قوت (سبکی، آفلاین، فارسی، ATS-friendly) در مارکتینگ و README.

### 11.3 سوالات باز (Open Questions)

- آیا باید از میان چندین فونت برای فارسی (Vazir، Vazirmatn، Sahel، Shabnam) انتخاب کاربر را فراهم کنیم، یا Vazir به‌عنوان پیش‌فرض تک فونت در MVP کافی است؟
- آیا داده‌های Profile باید به‌صورت فایل JSON تک یا در دیتابیس SQLite ذخیره شوند؟ JSON ساده‌تر برای انتقال و نسخه‌بندی است، SQLite برای query و موازی‌سازی بهتر است. پیشنهاد: JSON برای MVP.
- آیا باید وب frontend از همان code base (Blazor WASM) استفاده کند یا HTML static ساده با API؟ پیشنهاد: HTML static + ASP.NET Minimal API، برای حفظ سادگی.
- آیا لایسنس GPL، MIT یا Apache 2.0؟ پیشنهاد: MIT برای جذب maximum contributions.

## 14. واژه‌نامه و ضمائم

### 14.1 واژه‌نامه

| اصطلاح | تعریف |
|--------|-------|
| Native AOT | Ahead-Of-Time compilation در دات‌نت 8+ که باینری native بدون runtime تولید می‌کند |
| Lead-Based AI Workflow | الگویی که اپ یک prompt تولید می‌کند و کاربر با AI خارجی قالب می‌سازد و وارد می‌کند |
| ATS | Applicant Tracking System، نرم‌افزارهایی که رزومه‌ها را parse می‌کنند |
| Profile | مجموعه داده‌های یک رزومه (basic info + sections) |
| Template | فایل HTML/CSS با placeholderها برای رندر با Scriban |
| RTL/LTR | Right-To-Left / Left-To-Right جهت متن |
| Inline CSS | استایل داخل همان HTML به‌صورت `<style>` یا attribute، بدون فایل خارجی |
| Section | یک بخش از رزومه (مثلاً تجربه کاری، تحصیلات) |
